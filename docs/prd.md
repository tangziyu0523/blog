# 工程级个人博客系统 PRD

> 版本：v0.1（整理版）｜日期：2026-06-10｜作者：tangziyu｜状态：草案，待逐模块细化

## 1. 产品概述

### 1.1 定位

一个**工程级**的个人博客系统：既是内容平台（写作、阅读、互动、订阅），也是个人技术能力的展示载体（全链路可观测、AI 自动化、混合检索、实时统计）。单人开发、单人运维，但按多人协作的工程标准建设。

### 1.2 设计原则

- **单体优先**：单 Postgres + 单 Redis 能解决的，不引入新组件；每个新依赖必须有不可替代的理由。
- **可观测优先**：任何功能上线前必须有日志、指标、追踪三件套。
- **AI 是放大器不是噱头**：AI 功能必须服务于"降低写作成本"或"提升阅读价值"。
- **移动端是一等公民**：所有页面响应式，核心阅读路径移动端体验不打折。

### 1.3 目标用户

| Persona | 场景 | 核心诉求 |
|---------|------|---------|
| 博主本人 | 写作、运营、看数据 | 低摩擦写作、AI 辅助、清晰的数据仪表盘 |
| 技术读者 | 搜索/订阅技术内容 | 检索准、阅读体验好、能划线评论讨论 |
| 路过访客 | 搜索引擎/社交跳转进入 | 首屏快、移动端友好、不强制登录 |

## 3. 模块详细需求

### 3.1 用户系统（P0）

**注册/登录**
- 邮箱 + 密码注册，密码 bcrypt/argon2 哈希存储，绝不落明文。
- 登录签发 JWT（access 15min + refresh 7d，refresh 存 Redis 支持吊销）。
- GitHub OAuth：标准 authorization code flow；首次登录自动建账号并绑定 `github_id`，已有邮箱账号时支持绑定合并。
- 异常路径：密码错误 5 次锁定 15 分钟；OAuth 回调失败展示可重试提示。

**信息管理**
- 可编辑：昵称、简介、个人主页链接、邮件通知开关。
- 头像：客户端裁剪 → 预签名 URL 直传 S3 兼容存储（开发用 MinIO）→ 回写头像 URL。限制 ≤2MB，jpg/png/webp，服务端二次校验 MIME。

**数据埋点与仪表盘（P1）**
- 事件模型：`event_name` + `user_id` + `ts` + `props(jsonb)`，统一从前端 SDK 上报到 `/api/track`，批量写入。
- 关键事件：`page_view`、`post_read`（含阅读时长、滚动深度）、`search`、`like`、`comment`。
- 博主仪表盘：PV/UV 趋势、热门文章、搜索词 Top、读者地域/设备分布。

### 3.2 博客核心（P0）

**编辑器**
- Markdown 编辑器，左右分屏实时预览；支持代码块、表格、数学公式、图片粘贴上传（走对象存储）。
- 草稿自动保存（本地 + 服务端，30s 间隔）；发布需填标题、标签（≤5）、摘要（可 AI 生成）。

**展示**
- 文章页 SSR/SSG，代码高亮（Shiki）、目录 TOC、阅读进度条。
- 首屏 LCP ≤ 2.5s（移动端 4G），Lighthouse 移动端 ≥ 90。

**检索（混合）**
- 全文检索（P0）：Postgres FTS + `pg_trgm`，中文分词用 `zhparser` 或应用层分词；支持标题/正文/标签字段加权。
- 语义检索（P1）：发布时生成 embedding 存 `pgvector`；查询时全文 + 向量双路召回，RRF 融合排序。
- 验收：检索 P95 ≤ 300ms；语义检索能命中"同义不同词"查询（例如搜"性能优化"召回讲"加速"的文章）。

**热度排行榜（P1）**
- 热度分 = f(浏览, 点赞, 评论, 时间衰减)，参考 HN 公式：`score = (V + 3L + 5C) / (age_hours + 2)^1.5`，权重可配置。
- Redis ZSET 维护，定时任务每 10 分钟重算，榜单页直接读 ZSET。

**在线阅读人数（P1）**
- 文章页 WebSocket/SSE 心跳上报，Redis `SET post:{id}:online`（带 TTL）统计去重在线数，30s 粒度刷新展示。

**推荐（P2）**
- 基于文章 embedding 的相似文章推荐（"读完这篇还可以看"）；同风格用户推荐基于用户阅读向量均值。

### 3.3 互动（点赞 + 评论）

**点赞（P0）**
- 对象：文章、评论。幂等切换（点赞/取消），未登录引导登录。
- 计数：Redis 计数 + 异步落库对账，防刷：同用户同对象去重，IP 级限流。

**评论（P0）**
- 楼中楼：两级结构（顶层评论 + 回复），回复可引用某条回复（@提及 + 引文）。
- Markdown 子集（粗体/链接/行内代码），XSS 全量过滤；作者可删除自己文章下任意评论。
- 划线评论（P1）：选中文本弹出评论入口，锚定方案 = 文本偏移 + 前后文指纹（容忍文章小幅修改）；划线在正文以高亮呈现，点击展开侧栏评论。

### 3.4 订阅与通知（P1）

- 关注：作者、标签。被关注对象发新文章 → 站内通知 + 可选邮件。
- 通知中心：未读红点、分类（互动/订阅/系统），WebSocket 实时推送在线用户。
- 投递管道：BullMQ 队列异步扇出，失败重试 3 次进死信。
- 每日新闻/大会推送（P2）：AI 管道（见 3.6）产出的 digest 作为系统订阅源。

### 3.5 可观测性与运维

**日志（P0）**
- 全链路结构化 JSON 日志（pino），统一字段：`trace_id`、`user_id`、`route`、`latency_ms`。
- 日志聚合：Loki + Grafana 查询分析；错误日志告警（Webhook → 自己的通知渠道）。

**指标与追踪（P1）**
- OpenTelemetry SDK 埋全链路追踪；Prometheus 抓取 RED 指标（Rate/Error/Duration）；Grafana 统一看板。

**部署（P0）**
- `docker compose up` 一键拉起全部服务（web/api/postgres/redis/minio/loki/grafana）。
- CI（GitHub Actions）：lint → typecheck → test → build，main 分支增加镜像构建推送；CD 阶段二再上。

### 3.6 AI 自动化（P1/P2）

| 功能 | 描述 | 验收要点 |
|------|------|---------|
| 内容总结（P1） | 发布时自动生成 TL;DR 与摘要，作者可改 | 摘要 ≤150 字，生成 ≤10s，失败不阻塞发布 |
| 写作助手（P1） | 编辑器内：润色选中段落、续写、起标题（给 3 个候选） | 流式输出；用户显式触发，不自动改稿 |
| GitHub Trending 解读（P2） | 每日抓取 Trending，AI 生成中文解读，自动发布到固定栏目 | 定时任务 + 失败告警；标注 AI 生成 |
| 论文 Digest（P2） | 订阅 arXiv 分类，AI 摘要成周报 | 同上 |

- 统一 LLM 网关层：封装模型调用、重试、超时、token 用量记录（入指标系统）。
- 所有 AI 生成内容必须可人工编辑且明确标注。

### 3.7 趣味与扩展（P2，每项独立立项再细化）

- **MCP Server**：把博客暴露为 MCP 工具（搜索文章、读文章、发草稿），供 Claude 等 Agent 调用。
- **知识树**：文章按主题组织成树/图谱视图；任务栏展示写作计划。
- **留言墙 / 话题讨论**：轻量公共讨论区。
- **漂流瓶**：读者匿名留言随机漂流给其他读者。
- **小桌宠**：页面角落互动桌宠，参考 neal.fun 的趣味交互质感。

## 4. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | API P95 ≤ 200ms（不含 AI 接口）；文章页 LCP ≤ 2.5s |
| 安全 | OWASP Top10 覆盖：参数化查询、XSS 过滤、CSRF、限流、密钥不入库不入 git |
| 可用性 | 单机部署目标 99.5%；数据库每日备份，恢复演练 |
| 移动端 | 全页面响应式，核心路径（阅读/评论/点赞）触屏优化 |
| 合规 | 埋点数据匿名化选项；Cookie/隐私声明 |

## 5. 技术架构决策（摘要，详见 CLAUDE.md）

- **Monorepo**：pnpm workspace + Turborepo。
- **前端**：Next.js（App Router, SSR/SSG）+ Tailwind CSS。
- **后端**：NestJS 独立 API 服务。
- **数据**：PostgreSQL（唯一真相源，含 FTS + pgvector）+ Redis（缓存/计数/队列）+ MinIO/S3（对象存储）。
- **不引入** Elasticsearch/Kafka/微服务拆分——当前规模 Postgres + Redis + BullMQ 足够，留扩展缝。

## 6. 里程碑

| 阶段 | 范围 | 出口标准 |
|------|------|---------|
| M0 基建（1-2 周） | monorepo、CI、compose、骨架服务、日志 | `docker compose up` 全绿，CI 全绿 |
| M1 MVP（3-4 周） | 全部 P0：用户/文章/全文检索/点赞/评论/部署 | 真实可用，博主能发文，读者能读能评 |
| M2 增强（4 周） | P1：混合检索、排行榜、订阅通知、仪表盘、AI 总结/写作助手、指标追踪 | 各功能带验收数据上线 |
| M3 长尾（持续） | P2 逐项立项：推荐、MCP、Trending、桌宠等 | 每项独立 mini-PRD |

## 7. 风险

| 风险 | 应对 |
|------|------|
| 范围过大烂尾 | 严格按 P0→P1→P2 推进，P2 不进主计划 |
| 中文分词/混合检索效果差 | M2 前做检索效果评测集（20 条 query 人工标注） |
| AI 成本失控 | LLM 网关记录 token 用量 + 月度预算告警 |
| 单人运维负担 | 一切告警自动化，compose 一键重建 |
