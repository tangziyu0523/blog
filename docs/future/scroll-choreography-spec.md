# 首页滚动编排规格（Scroll Choreography）— 未来增强规格

> 状态：**规划中**，依赖水墨交互层（见 [`ink-interaction-spec.md`](./ink-interaction-spec.md)）基础骨架完成后实现。
> 性质：纯前端叙事编排层，**不影响数据流与 SEO**，作为 `feat/ink-layer` 分支的后续阶段开发。

## 定位

首页滚动叙事分为两段，从「策展叙事」平滑过渡到「常规索引」：

1. **翻书段**——Hero + 2~3 个作者级「书页」，走翻书转场。
2. **索引段**——往下「开书成索引」后，文章列表回归常规垂直滚动 + 轻量逐词显影。

水墨交互层（`InkCanvas`）作为两段共同的背景层持续存在，不参与编排逻辑。

## 内容模型（核心决策）

| 段落 | 内容来源 | 是否随文章流变化 |
|------|----------|------------------|
| 翻书段（Hero + 2~3 书页） | **固定策展内容**，手工编排 | ❌ 否 |
| 索引段（文章列表） | 动态文章流（`fetchPublishedPosts`） | ✅ 是 |

**铁律：翻书只绑定固定策展内容，不绑架动态文章流。**

- 翻书页是作者级的精选叙事单元，由人工策展，与文章的发布 / 删除 / 排序解耦。
- 文章数量变化（新增、下架）只影响索引段，翻书段结构稳定不受影响。
- 「开书成索引」是两段之间的转场锚点：翻完最后一页书 → 索引段以常规滚动接管。

## 编排分解

| 阶段 | 交互 | 动画手法 |
|------|------|----------|
| Hero 入场 | 进入首页 | 水墨显影 + 标题逐词淡入 |
| 翻书转场 | 滚动驱动（pin + progress） | 3D `rotateY` 翻页，一页一屏 |
| 开书成索引 | 翻完书页 | 解除 pin，书页「摊开」为列表起点 |
| 索引滚动 | 常规垂直滚动 | 沿用现有 `ScrollReveal` 逐行 / 逐词显影 |

## 技术映射

- **翻书**：GSAP `ScrollTrigger` 的 `pin` + scrub，配合 CSS 3D `rotateY` / `transform-origin`。
- **逐词显影**：复用现有 `ScrollReveal`（`gsap.to` + `ScrollTrigger`，仅 transform + opacity）。
- **背景水墨**：`InkCanvas` 持续渲染，翻书段不打断其循环。
- 不新增依赖：GSAP + `@gsap/react` 已在 baseline 引入。

## 工程约束（必须实现）

1. **降级矩阵延续水墨层**：`prefers-reduced-motion` 命中时翻书降级为直接堆叠 / 简单淡入；移动端简化或跳过翻书，直接进入索引段。
2. **策展内容缺失时优雅收缩**：策展书页不足 2~3 篇时，翻书段按实际数量收缩，最少可退化为「仅 Hero + 索引」。
3. **不阻塞首屏**：编排为渐进增强，SSR 输出的静态内容必须独立可读，JS 失败不影响阅读。
4. **数据解耦**：翻书段的策展内容来源独立于文章查询，二者不共享分页 / 排序状态。

## 降级矩阵

| 条件 | 翻书段 | 索引段 |
|------|--------|--------|
| 桌面 + 允许动效 | 完整翻书转场 | 逐词显影 |
| `prefers-reduced-motion` | 直接堆叠，无翻页 | 直接显示，无显影 |
| 移动端 | 简化 / 跳过 | 常规滚动 |
| 策展内容不足 | 按数量收缩 | 不受影响 |

## 待定（Phase 1 细化）

- 策展书页的内容结构与存储方式（手工配置 vs. 独立标记的精选文章）。
- 翻书段每页的版式（与博物学设计规范的衔接）。
- 「开书成索引」转场的具体缓动与锚点定位。

## 依赖与排期

- **前置依赖**：水墨层 Phase 1/2 骨架完成。
- **开发方式**：`feat/ink-layer` 分支后续 Phase，逐阶段推进。
- **优先级**：可选增强，P0/P1/P2 主线功能完成前不动手。
